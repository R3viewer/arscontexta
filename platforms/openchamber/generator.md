# OpenChamber Platform -- Generation Reference

## Generator Source

The `AGENTS.md` generation logic lives at `generators/agents-md.md`. That file contains the complete template for composing an `AGENTS.md` context file from feature blocks, vocabulary mappings, and personality dimensions.

## What OpenChamber Platform Generates

An OpenChamber / OpenCode deployment produces:

### 1. AGENTS.md (Context File)

The primary context file, auto-loaded and hot-reloaded by OpenCode at session start. Composed from selected feature blocks (see `platforms/shared/features/`) with domain vocabulary applied. Contains:

- Philosophy and operating principles
- Discovery-first design (tree injection, YAML queries, MOC navigation)
- Note design patterns (titles as claims, composability test, link semantics)
- Processing pipeline or light-processing workflow
- Maintenance and self-evolution guidance
- Session rhythm (orient, work, persist)
- Ethical guardrails

Generated by: `generators/agents-md.md`

### 2. .arscontexta (Vault Marker & Config)

The vault marker file that enables Ars Contexta plugin hooks in OpenCode:

```yaml
# Ars Contexta vault marker + config
git: true
session_capture: true
```

### 3. opencode.jsonc (Project Configuration)

OpenCode project configuration file configuring:

- Semantic search MCP server (when qmd is enabled):
  ```jsonc
  {
    "$schema": "https://opencode.ai/config.json",
    "mcp": {
      "servers": {
        "qmd": {
          "type": "local",
          "command": ["qmd", "mcp"]
        }
      }
    },
    "permissions": [
      { "action": "qmd_*", "resource": "*", "effect": "allow" }
    ]
  }
  ```

### 4. Generated Skills & Commands (.opencode/skills/ & .opencode/commands/)

Domain-transformed skills and slash commands generated from `skill-sources/` with the user's domain vocabulary applied:

- `.opencode/skills/[domain-skill-name]/SKILL.md`
- `.opencode/commands/[domain-skill-name].md`

### 5. Automation & Hooks

Supplied automatically by the bundled Ars Contexta OpenCode V2 server plugin (`plugin/`):
- `session-orient`: Workspace tree injection, `self/` orientation, and condition-based maintenance signals.
- `write-validate`: Schema and frontmatter enforcement on note writes.
- `auto-commit`: Serialized async Git auto-commit.
- `session-capture`: Automatic session state persistence in `ops/sessions/`.

## Platform Characteristics

| Aspect | Detail |
|--------|--------|
| Context loading | `AGENTS.md` auto-loaded & hot-reloaded by OpenCode |
| Hook implementation | Native Node.js ESM server plugin (`plugin/index.js`) |
| Hook events | `ctx.session.hook("context")`, `ctx.tool.hook("execute.after")`, `ctx.event.subscribe` |
| Skill format | `.opencode/skills/[name]/SKILL.md` |
| Command format | `.opencode/commands/[name].md` |
| Agent format | `.opencode/agents/[name].md` |
| File access | Native filesystem via OpenCode server |
| MCP support | Configured via `opencode.jsonc` |
